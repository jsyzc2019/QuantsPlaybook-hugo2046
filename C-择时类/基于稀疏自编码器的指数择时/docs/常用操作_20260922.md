# 如何离线读取、调整参数和导出结果

先完成[新人教程](使用指南_20260922.md)。以下 Python 片段在已运行导入及配置单元格的 notebook 中执行；参数定义见[参数参考](参数参考_20260922.md)。

## 严格离线读取已有行情

数据库必须已包含所需行情和交易日历。替换原取数单元格的调用：

```python
from src.data_provider import load_index_dataset
from src.store import DEFAULT_DB_PATH

index_df = load_index_dataset(DEFAULT_DB_PATH, START, END, code=CODE)
print(index_df.index.min(), index_df.index.max(), index_df.shape)
```

此函数不联网、不补数据。检查返回日期是否满足自己的训练及测试需求；它会回溯最多600个交易日读取已有预热数据，但不会创造缺失历史。当前 notebook 的 `FETCH` 变量未参与控制流，设为 `False` 不会禁止 `get_index_dataset` 联网。

## 调整时间、指数或训练参数

取数参数和研究配置须保持一致。以下以当前中证500为可运行示例，修改 `CODE` 时也要更新图表标题，并核对新指数的换手率覆盖与训练历史。

```python
from src.data_provider import get_index_dataset
from src.generator import ResearchConfig, SAETimingGenerator

CODE = "000905.SH"
START, END = "2005-01-01", "2025-12-31"
config = ResearchConfig(
    code=CODE, train_start=START, test_start="2020-01-01",
    test_end=END, seeds=tuple(range(10)), threshold=0.002,
)
index_df = get_index_dataset(START, END, code=CODE)
result = SAETimingGenerator(config).run(index_df)
print(result.folds)
```

`config.code` 只标记预测结果，不会替你切换输入行情。修改 `horizon` 会改变标签，必须重训；只比较信号阈值时可复用已得到的 `score`：

```python
from src.analyze import threshold_performance

score = result.predictions["score"].droplevel("code")
close = index_df["close"].reindex(score.index)
comparison = threshold_performance(close, score, thresholds=(0, 0.002, 0.004))
print(comparison)
```

不要以同一测试区间内收益最高的参数作为已验证的最优参数。若只是确认流程能运行，可减少 seed 或训练轮数；这种结果不能与完整配置直接比较。

## 导出预测与折划分

先完成训练。选择一个尚不存在的输出目录，避免覆盖此前结果：

```python
from pathlib import Path
from src.store import DEFAULT_DB_PATH

output_dir = DEFAULT_DB_PATH.parent / "exports_first_run"
output_dir.mkdir(parents=True, exist_ok=False)
result.predictions.to_csv(output_dir / "predictions.csv")
result.folds.to_csv(output_dir / "folds.csv", index=False)
print(output_dir)
```

该操作只导出两张表，不保存完整模型，也不登记 DuckDB 实验。保存完整实验需显式使用存储层；当前项目没有旧版 CLI 脚本。

## 验证安装与排查

在策略目录执行离线测试；缓存目录放在被忽略的 `data/` 下：

```bash
NUMBA_CACHE_DIR="$PWD/data/numba_cache" MPLCONFIGDIR="$PWD/data/mplconfig" python -m pytest tests -q
```

| 现象 | 处理 |
|---|---|
| `No module named src` | 内核工作目录应为策略目录或其 `notebook/`，重新运行导入单元格。 |
| 找不到 torch、talib 等依赖 | 在当前内核对应的 Python 中安装 requirements，安装后重启内核。 |
| Jupyter 命令不存在 | 执行 `python -m pip install notebook ipykernel`，再用 `python -m notebook` 启动。 |
| DataFeed 不可用但随后正常读数 | 这是预期回退提示，无需安装私有模块。 |
| `未配置TS_TOKEN` | 检查策略目录 `.env` 是否填写；修改已有环境变量后重启内核，避免旧值继续生效。 |
| `index_basic未返回`、接口无列空表或首次拉取零行 | 检查代码、账号接口权限、网络和服务返回；不要把空返回当成有效历史。 |
| 真实换手率缺失 | 核对该指数数据覆盖，不要填零；`volume_proxy` 属于改变研究口径，也不能保证补救接口拼接零行。 |
| `样本外存在warm-up空缺`、`训练样本不足一个batch` | 提供更早历史或推迟测试起点，并检查 `result.folds` 的实际训练日期。 |
| `rsi_form='ratio'` 导致缺失 | 默认使用 `bounded`；原比值形式仅用于明确的对照研究。 |
| DuckDB 锁冲突或旧库迁移要求独占 | 关闭占用同一文件的连接或其他内核后重试，不要直接删除数据库。 |
| Numba 报 `no locator available` | 启动前设置上述可写的 `NUMBA_CACHE_DIR`；重启已导入 vectorbt 的内核。 |
| 改参数后图表没变化 | 从受影响的最早单元格顺序重跑，检查是否仍引用旧的 `result/score/frames`。 |
